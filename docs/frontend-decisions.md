# Frontend decisions

1. **Simulation-first scope.** The pitch and prototype specification describe a fictional concept demo. This build does not connect to real ports. The architecture blueprint supplies future service boundaries; its suggested real Django domain apps are deferred because the master implementation prompt explicitly limits the backend to a health scaffold.
2. **Existing source directory.** The supplied files were under `doc/`, singular, while the master prompt assumed `docs/`. The originals remain untouched in `doc/`; new implementation documents live in `docs/`.
3. **Local map.** MapLibre 6 uses a checked-in same-origin module worker (`frontend/public/maplibre-gl-worker.mjs`) and an empty style with locally generated GeoJSON. The canvas layer renders moving entities and avoids 2,000 React container nodes. Map coordinates are fictional world coordinates transformed to tiny synthetic longitude/latitude values.
4. **One demo state.** Zustand owns the seeded normalized snapshot. Portal views, inspector and scripted copilot read it. A 100 ms fixed-step loop changes the simulation clock and aggregate counters; canvas uses animation frames to derive motion from that clock.
5. **Safety and approval.** A point-in-polygon rule causes the scripted zone breach. Approval is explicit, idempotent and logged. The safety crane hold is not cleared by the recovery proposal.
6. **Privacy.** Named fictional worker records are display-only. All standard demo roles get zone-level inspector positions; the demo supervisor gets exact fictional coordinates. The future backend must enforce this before sending DTOs.
7. **API mode.** The current backend has no domain API. API mode displays unavailable status and never quietly falls back to demo values. The BFF and typed data-source interface are a future integration seam; product views still use the simulation store until an authoritative API snapshot and event stream exist.
8. **Local dependencies.** Docker builds install Node and Python packages. Fonts are bundled from Fontsource, and no runtime CDN, external tiles or AI service is used.
9. **Visual refresh and theme choice.** Following the user's request for a more aesthetic interface, the frontend now uses a maritime visual system, a locally generated Three.js terminal model, a tilted MapLibre map with extruded structures, and animated route, surface, card and drawer transitions. One header switch chooses dark or light throughout the UI and map, persists in local storage, and restores before first paint. The 3D inset can be hidden, pauses offscreen, and respects reduced-motion settings. The modern dual palette follows the user's later request while preserving the same fictional operations and data boundaries.

Known limitations and measured outcomes are in [implementation-status.md](implementation-status.md).
